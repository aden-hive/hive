# Hive v1.0.5: Branch Anywhere

> Branch a conversation at any message to try another way, and every conversation names itself.

## New

- **Branch a conversation at any message.** Every queen reply has a **Branch from here** button:
  it opens a new conversation that ends with that reply, so you can take it somewhere else without
  losing the original. Every message you sent has **Edit in a new branch**: the new conversation
  ends just before that message, which is back in the composer, with its files, for you to change
  and send again. A branch carries the conversation and the files in it; its Action Plan starts
  empty, and the original conversation is not touched. A point that has been compacted out of the
  queen's context can't be branched from, and Hive says so.
- **Conversations name themselves.** After the queen's first reply, the worker model (the one set
  for workers in Settings, else the queen's own) gives the conversation a short title, in the
  language you write in. The session switcher shows titles instead of dates, marks branches, and
  lets you rename a conversation; a name you give it is never replaced.

## Fixed

- **Creating a queen.** Creating a queen from the dashboard answered with an error although the
  queen had been saved, and trying again then said the queen already existed. It now succeeds.

## For code built on Hive

A new event, `EventType.SESSION_TITLE_UPDATED` (`session_title_updated`), carries
`{session_id, title}`. The server has two new routes: `POST /api/sessions/{id}/fork`, with an
optional `before_input_at` (the timestamp of the user message to cut before), returns the new
session; `PATCH /api/sessions/{id}/title` sets or clears a title. Session history entries have
`title` and `forked_from`.

`aden-tools` is released at the same version, unchanged, because the `tools` extra pins it exactly.
