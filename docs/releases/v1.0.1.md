# Hive v1.0.1: Build on Hive

> Hive's primitives can now be used from your own project: depend on `aden-hive` and
> `from hive import AgentLoop, LiteLLMProvider, EventBus, ...`. See
> [Building on Hive](../building-on-hive.md).

## What's new

- **The `hive` package** exports the agent loop, model providers, tool types, stream events, the
  event bus, colonies, storage, configuration and `SSEResponse` from one place. Each name is
  imported when first used, so `import hive` takes a few milliseconds.
- **`AgentLoop(on_report=...)`** gives any agent the `report_to_parent` tool and hands its report
  to your callback as an `AgentReport`. Before, only colony workers on a `worker:` stream could
  report, and only to a `Worker`.
- **A light install.** Hive's built-in tools (`aden-tools`, with a browser, PDF and OCR libraries,
  and database and SaaS clients) moved to the `tools` extra. A project that depends on Hive now
  installs 83 packages instead of 123.
- **Lighter imports inside Hive.** `framework` and `framework.host` import their classes when first
  used, so importing one module (for example `framework.host.event_bus`) no longer loads the
  colony runtime.
- Typing markers (`py.typed`) for `hive` and `framework`. `AgentContext.runtime` accepts `None`.

## Changed

- The packages are renamed `aden-hive` (was `framework`) and `aden-tools` (was `tools`). The old
  names clashed with unrelated packages on PyPI, so an installer outside this workspace could
  fetch the wrong `tools`. Import names are unchanged: `framework`, `aden_tools`.
- The version in `core/pyproject.toml` now matches the release (it had stayed at 0.7.1).

Nothing changes for Hive itself: `uv sync` in this repository still installs the built-in tools
(through the new `app` dependency group), and the quickstart, `hive open` and the desktop build
work as before.
