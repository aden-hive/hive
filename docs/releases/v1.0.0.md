# 🐝 Hive Agent v1.0.0: Colonies, Built-in Tools, and Measured Memory

> Hive V1 rebuilds how a colony runs. A queen does the work herself first, then turns it into a colony that coordinates through a shared SQLite tracker and runs at scale with playbooks. Hive's own tools now run inside Hive, with no tool servers to start; thirteen queens ship with it; models are configured your way; and, for the first time, we publish how well a queen's memory works.
>
> ⚠️ **Upgrading from v0.11:** saved sessions and the `~/.hive` layout migrate automatically on first start, but V1 replaces v0.11's colony workflow (incubation, `run_parallel_workers`, `progress.db`) and its browser tools. Prompts, automations and custom agents written against the v0.11 tools need updating; see **Breaking changes and removals** below.

---

## ✨ Highlights

### 🐝 Colonies, rebuilt around a shared tracker

A queen no longer designs a colony up front. She **executes first, then systematizes**: she does one unit of the work herself, and when the work turns out to be parallel, recurring or long-running, she suggests a colony.

- **Two phases instead of four.** A queen is either working on her own (`independent`) or running a colony (`colony`). She proposes the switch with `suggest_colony`, and you confirm it in the Create Colony dialog. The v0.11 incubating, working and reviewing phases are gone, and old sessions map to the new phases on load.
- **A shared SQLite tracker per colony.** The queen designs the colony's tables (`tracker_sql`, `tracker_register_writable`), workers write one row per unit of work (`tracker_upsert`), and the queen checks progress with SQL. It replaces v0.11's `progress.db` task queue.
- **`run_worker`** spawns a worker clone of the queen, with the same tools and model and its own task, whenever she needs one.
- **Playbooks.** `run_playbook` dispatches one worker per tracker row that isn't done yet, with retries and backoff, rate-limited lanes, a circuit breaker and a dead-letter list. The tracker is the source of truth, so re-running a playbook resumes it. `get_playbook_status`, `stop_playbook` and `list_playbook_runs` manage runs.
- **Skills from a working pilot.** Once a pilot works, the queen records the protocol as a colony skill with `write_skill`, and every worker she spawns afterwards can load it.
- **Scheduled colonies** with cron, interval and webhook triggers. Runs missed while Hive was stopped are caught up after you confirm them.

### 👑 Thirteen queens, and you choose who takes the job

- **Thirteen persona queens**, up from eight, defined as YAML profiles. New in V1: Content, Lead Generation, Market Research, Outbound and RevOps.
- **Six are active out of the box** (Growth, RevOps, Content, Lead Generation, Outbound, Brand & Design). Hire the rest from the Org Chart, or create your own with **New Queen**.
- **You pick the queen.** The automatic queen router is retired; type a request on Home and choose who takes it.
- **Clearer collaboration:** questions with options (`ask_user`), a task plan you can watch, and a confirm dialog before any colony is created.
- **The Prompt Library** deploys a ready-made prompt straight to the queen it was written for.

### 🧰 Built-in tools that run inside Hive

- **No tool servers to start.** Hive's own tools run in-process, grouped as `terminal-tools` (shell, background jobs, ripgrep and glob search), `files-tools`, `chart-tools`, `memory-tools` and `hive_tools` (attachments, PDFs, web scraping, CSV, image generation and more). A queen boots with no MCP subprocesses.
- **External MCP servers** still work. Add them with `hive mcp add` or `hive mcp install`; their tools join the same allowlists as the built-in ones.
- **Shorter prompts with on-demand tools.** A small always-on set loads up front; everything else a queen is allowed to use appears in a manifest she loads with `search_tools`. Tool categories plus per-queen and per-colony allowlists decide what she may use, and `search_tools("inventory")` lists what is loaded, searchable, disabled or unavailable.
- **Your own Chrome.** The Hive Browser Bridge extension and the `hive-browser` CLI replace the `browser_*` tools. A long-lived bridge keeps tabs alive across restarts, each worker gets its own tab group, and one colony can drive several Chrome profiles.
- **Better coding tools.** An opt-in **Read & edit code** category (`read_file`, `edit_file`; on by default for the Technology queen) preserves line endings and guards against stale edits. `terminal_exec` kills whole process trees and moves slow commands to the background after 5 seconds, to be collected later with `collect_result`. `terminal_rg` gains a `context` option, and `terminal_glob` supports `**` and `{a,b}` patterns.
- **New tools:** `attach_file` shows a file to you and re-reads it into context; `image_generate` creates and edits images through Hive LLM; a single `credentials` tool asks for secrets through a secure form instead of the chat.
- **Skills** in the open [Agent Skills](https://agentskills.io) format, managed in the Skills Library. You can import skills from other agents' folders (Claude, Codex, Cursor, Gemini), and Hive suggests ones it finds.

### 🧠 Memory, measured

V1 is the first Hive release with a published memory benchmark. We run [LongMemEval](https://arxiv.org/abs/2410.10813), the benchmark most agent-memory products report, end to end through Hive: each question's chat history is stored as real past queen sessions, and a fresh queen answers with nothing in her context except what Hive's memory surfaces. Answers are graded by the official LongMemEval judge (gpt-4o-2024-08-06).

| | LongMemEval-S (~115k tokens of history per question) | LongMemEval-M (~1.1M tokens per question) |
|---|---|---|
| **Hive V1** | **88.4%** | **82.0%** |
| Hive before V1 | 77.0% | – |
| Same model, whole history in context, no memory system | 96.8% | not feasible |
| Same model, only the sessions that hold the answer | 97.6% | 97.8% |

All rows use `gpt-6.1-sol` as the answering model, on all 500 questions.

We're publishing the uncomfortable row too. **When a user's whole history fits in the model's context, reading all of it is still more accurate than Hive's memory**: 96.8% against 88.4% on LongMemEval-S. On LongMemEval-M, where no model can read the whole history, memory is the only option, and Hive answers 82.0% of questions. The methodology, per-type results, a comparison with Honcho, Mastra, Zep and others, and every limitation we know of are in **[Memory benchmark: LongMemEval](../memory-benchmark.md)**.

What changed in memory:

- **The queen checks her memory before asking you.** Questions about your own life, plans or history trigger a search of past conversations first, even when you don't mention an earlier conversation.
- **Automatic recall of past conversations.** Before each message, Hive places up to six dated excerpts from related earlier sessions in front of the queen, so recall doesn't depend on her deciding to search. She can also search all past sessions herself with `search_messages`, which now honours its date filter.
- **Reflection notes**, kept globally and per queen, are recalled into context when they're relevant, and you can browse and edit them in the new **Memory Library**.
- **Optional dated timeline** (`memory_timeline` feature flag, **off by default**). Hive can keep a dated timeline of the events, facts and plans you mention, searchable with `search_timeline`. Its measured gain was small and not statistically clear, and it costs a background model call every few messages, so it ships off.

Known gaps we're working on next: preference questions in very large histories (30% on LongMemEval-M), recalling what the assistant itself said earlier (about 77–79%), and counting across many sessions (about 79–82%).

### 🔌 Any model, configured your way

- **Bring your own key.** Settings lists providers (Anthropic, OpenAI, Gemini, Groq, Cerebras, MiniMax, OpenRouter, Mistral, Together, DeepSeek and more). Add a key, Hive checks it, and you pick a model. Any [LiteLLM](https://docs.litellm.ai/docs/providers) provider, coding subscriptions (Claude Code, OpenAI Codex and others), Hive LLM and Ollama also work.
- **Custom OpenAI-compatible endpoints** (vLLM, proxies) are a first-class choice, with any model name.
- **Three model slots:** the main model, a separate model for workers, and a vision fallback that captions images for text-only models. Changing the main model takes effect in running sessions without a restart, and a **provider library** stores named configurations you can apply to any slot.
- **Thinking models:** reasoning streams live into a collapsible activity block, and one `llm.aux_max_tokens` setting replaces many small hard-coded output limits that left reasoning models returning empty replies.
- **Context limits follow the model.** The context window comes from your configuration or the model catalog, so a 32k local model no longer runs with a 180k compaction budget.
- **Images reach the model.** On APIs that can't carry images inside a tool result, screenshots and attachments are moved into the next user message instead of being dropped silently.

### 🛡️ Keeps working while you're away

- **Sentinel** (opt-in per colony). When a colony queen parks, a classifier decides whether to nudge her on, mark the work done or escalate to you through Telegram or Slack (or the Hive inbox, with a Hive cloud account). Your reply resumes her.
- **A reminder hub** keeps the right context in front of every agent: an idle nudge, a retry when a stream stalls, a recap of workers still running, and tracker snapshots.
- **Park and resume from disk** after a question, a stop, an error or a crash; **context compaction** with large tool results spilled to files; **stall and doom-loop detection**; tool-call budgets per turn and per run, and a cap on concurrent workers.
- **Usage metering** on every model call, a persistent server log at `~/.hive/logs/hive-server.log`, and a `hive janitor` command for data retention (dry-run by default).

### 🖥️ A new dashboard

- **The Hive map** on Home: each queen sits in a honeycomb with her colonies around her, each marked Working, Needs you or Idle, with live counts above.
- **Colony pages** with the tracker as a data grid (Data, Plan, Automations and Workers), a scheduler, and "Needs you" badges with OS notifications.
- **Chat:** syntax-highlighted code blocks with copy buttons and coloured diffs, an image gallery for attachments, attachments of any type saved to disk for the agent, a `/` menu for skills, and parallel sessions in the session switcher.
- **Polish:** a first-run tour, a connectivity banner, startup progress during a cold start, a "Report a problem" bundle with credentials scrubbed, and a Settings → Motion option (System, Full or Reduced) for the new animations.

## ⚠️ Breaking changes and removals

**Queen and colony tools**
- Removed: `start_incubating_colony`, `cancel_incubation`, `create_colony`, `switch_to_reviewing`, `stop_worker_and_review`, `run_parallel_workers` and `enqueue_task`. Use `suggest_colony`, `run_worker`, the tracker tools and `run_playbook`.
- Workers no longer wait on the queen for answers (`list_worker_questions` and `reply_to_worker` are gone); they escalate with the `escalate` tool.
- The automatic queen router is retired. You choose the queen; the `/queen-routing` page redirects to Home.

**Tools**
- **Bundled MCP server subprocesses are retired**, including `gcu-tools`. Hive's tools run in-process, and old auto-installed entries are removed from `installed.json` on first start.
- **The `browser_*` tools are replaced by the `hive-browser` CLI.** Update the Hive Browser Bridge extension.
- **The bundled third-party integrations** (Gmail, Calendar, Google Docs and Sheets, GitHub, HubSpot, Notion, Slack, security scanners and others) are no longer loaded, and their tool categories and Connect cards are gone. The full catalog in `tools/` can still run as an external MCP server; see [Tools](../tools.md).
- **ripgrep is required.** The quickstart installs it; without it, `terminal_rg` returns an error unless the call passes `allow_fallback=True`.
- `edit_file` fails on an ambiguous match unless `replace_all` is set; `terminal_glob` now respects `.gitignore`; `terminal_exec` caps foreground waits at 220 seconds.
- The `excel_*` tools appear only when `openpyxl` is installed (the `tools[excel]` extra).

**HTTP API**
- Removed session endpoints: `/api/sessions/{id}/{trigger,inject,pause,resume,stop,replay,goal-progress,colony-spawn,entry-points,task_list_id}` and `/api/sessions/{id}/colonies/*/nodes*`. Also removed: `/api/tasks/{id}`, colony skill CRUD under `/api/colonies/{name}/skills*`, and the logs API.

**Configuration and data**
- `~/.hive` moves to layout v3, migrated automatically on first start. External scripts that read the old paths need updating.
- The managed `hive` model provider is hidden unless `HIVE_CLOUD_BASE` is set, and choosing it no longer skips model setup.
- An `api_key` written in `configuration.json` now takes precedence over environment variables and subscriptions.
- The Kimi model id is corrected to `kimi-k2.5`; update configurations that used `kimi-2.5`.

**Removed from the repository**
- The example agent templates (use the Prompt Library) and the credential tester agent.
- Graph-era reference docs and about 7,500 lines of dead code.

## 🐛 Notable fixes

- A new colony's queen starts working immediately instead of waiting for you to repeat the request.
- Creating a colony from a short chat no longer waits on compaction, and compaction no longer requests oversized summaries that timed out.
- Shutting down a colony no longer hangs on an unresponsive browser bridge.
- Recalled memories no longer wake an idle queen, which sometimes made her answer the same message twice.
- A Stop that lands just as the queen asks a question is no longer lost.
- The UI no longer freezes until a refresh: one shared event stream, a stall watchdog, and no lost queued messages. Heavy parsing moved off the server's event loop.
- Concurrent file writes no longer corrupt each other.
- The live workers panel shows each worker's real start time.
- `attach_file` finds files in the agent's working directory.
- MCP servers that never finish their handshake now fail fast instead of being treated as connected.
- Gemini through Antigravity: tool schemas are sanitized for Gemini, and the client identifies as a current Antigravity version.
- On Windows, colony uploads no longer land in the wrong temp directory, and `quickstart.ps1` offers to install the Hive Browser Bridge extension.
- The quickstart scripts and getting-started guide point to the current Discord invite.

## 🧪 Testing and CI

- CI on Ubuntu and Windows runs the core, framework and tools test suites, and verifies ripgrep.
- **Live end-to-end specs** (`core/tests/e2e`) run a real queen against a real model and check her results against ground truth: file work, vision, data analysis, log forensics, bug fixing, feature work from a spec, memory recall, session resume and multi-turn follow-ups.
- **LongMemEval** runs end to end through Hive on S or M, with tools to re-grade saved runs with the official judge and to run the reference conditions.

## 🚫 Not in this release

- **The team CRM** is not part of the open-source build. Its queen instructions and tools are switched off when the CRM package isn't present.
- **No desktop app** ships; desktop-only features are stubbed out in the web build.
- **Cloud-dependent features** need a Hive cloud account: the email senders suite (also off unless `HIVE_EMAIL_SENDERS` is set) and the Sentinel Hive inbox channel.
- Spend limits in dollars, enterprise secret managers, PyPI and Docker packages, semantic memory search and a JavaScript SDK are still open. See the [roadmap](../roadmap.md).
