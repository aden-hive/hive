# Hive v1.0.15: Notes in Time

> A queen's memory notes now reach her before she answers, not a message late. Every change to a
> note is kept and can be undone, and the notes you write stay yours. Recall no longer holds up a
> message, and a long tool wait no longer costs model turns.

## New

- **Her notes reach her before she answers.** A model used to pick the notes for each message after
  she had started answering, so they arrived mid-turn or with the next message. On 108 LongMemEval
  questions they reached her on only 4. Now, by default, she is shown every note's name and
  one-line description (in full when a session starts and after a compaction, then only what
  changed) and opens the ones she needs, with no extra model calls. The other choice is to wait for
  the model's pick before she answers, up to `wait_seconds` (10). On those 108 questions
  (preferences and facts that changed over time), with `gpt-6.1-sol` answering, both new ways
  answered 101 correctly, against 96 for the old one and 94 with no notes at all. Waiting for the
  pick added about 2 seconds a reply. See
  [configuration.md](../configuration.md#how-memory-reaches-a-queen).
- **Settings → Memory.** Choose how notes reach her and which model writes them. A change reaches
  running sessions from their next message, chat-app sessions included, with no restart.
- **Every change to a memory note is kept.** Each memory folder keeps `log.jsonl`: who changed a
  note, why, and its text before and after. On the Memory page a note shows its history and can go
  back to any earlier version, and notes that were deleted are listed with who deleted them and why,
  ready to restore.
- **The notes you write are yours.** A note you write or edit on the Memory page is marked as yours.
  Reflection won't change or delete it, and writes what it learns to another note instead. A note
  from before this release belongs to nobody until you first edit it.
- **A note's age counts from when it was last confirmed.** Each note records the day it was learned
  and the last day a conversation confirmed it, and recall gives its age from that day. Tidying a
  note up no longer makes an old fact look new.

## Changed

- **Memory is written by the worker model.** Reflection and the dated timeline now use the
  `worker_llm` model by default, or her own model when none is set. `"memory_reflection": {"model":
  "main"}`, or Settings → Memory, puts them back on her model.
- **Recall doesn't hold up a message.** Before each message, recall searched every cached turn on
  disk: about 1.2 seconds on a store of 15,000 turns, and sometimes the whole 8-second limit with
  nothing found. It now reads a small per-queen index, in about 30 milliseconds, with the same top
  results, and the limit is 3 seconds. The index builds in the background on the first message after
  you upgrade (about 19 seconds for 15,000 turns) and can be deleted at any time.
- **A long wait costs no model turns.** Waiting on a terminal job or a worker's result used to stop
  after 45 seconds, and each repeat was a model turn. Hive now waits for her, up to 10 minutes,
  checking every second. A new message from you ends the wait, and she gets what has arrived so far.
- **Task updates ride along with real work.** Rounds that only updated her task list were 30% of
  model time. Models other than Anthropic's are now asked for parallel tool calls (an endpoint that
  refuses is asked again without them), and she updates tasks in the same response as the step's
  tool call. In a chat app, where you can't see the task panel, she plans only longer work.
- **Saved setups on the Models page.** Saved model setups sit beside endpoints and API keys and are
  offered first in the model lists. A setup never shows any part of its key.

## Fixed

- **A message sent while she works arrives in time.** A message that came in while her tools ran
  joined the conversation one response late. It now goes in before her next response, and its text
  no longer leaks into the next recall.
- **A chat app hears her as she works.** A channel got her text only when a model turn finished,
  which could be many tool calls later, and a later turn's text could replace it. Text written
  before a tool call now arrives as the tool starts.

## For code built on Hive

- `QueenOutput` has a new kind, `"idle"`: she has stopped to wait for the next message, the moment to
  clear a "typing" indicator. It carries no text. A channel should ignore kinds it doesn't handle;
  hive-onebot 0.3.2 and older treat it as an empty message.
- Memory files' frontmatter gains `author` (`owner`, `queen` or `reflection`), `learned` and
  `confirmed`, and each memory folder gains `log.jsonl`. `framework.agents.queen.memory_log` writes,
  retires and restores memory files; code that writes them directly bypasses the log and the owner's
  protection.
- New endpoints: `GET /api/memories/history`, `POST /api/memories/restore`,
  `GET /api/memories/retired`, `GET` and `PUT /api/config/memory`.
- New configuration: `memory_recall` (`mode`, `wait_seconds`; `HIVE_MEMORY_RECALL` overrides the
  mode). `memory_reflection.model` now defaults to `"worker"`.
- `LoopConfig.tool_wait_limit_seconds` (600) caps how long the loop waits on a tool's job.
- The LongMemEval runner can build the notes a seeded history would have left
  (`HIVE_LME_NOTES=1`).

`aden-tools` is released at the same version, with the recall index above. The two packages pin each
other exactly.
