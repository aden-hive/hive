# Hive v1.0.4: Reasoning Remembered

> Qwen, DeepSeek and GLM keep their train of thought across the steps of a turn, and saving a
> provider works in an installed Hive.

## Fixed

- **Reasoning streamed as `reasoning_content` is sent back.** Qwen, DeepSeek and GLM on their own
  endpoints stream their reasoning as the OpenAI-compatible `reasoning_content` string. Hive showed
  it live but never kept it, so on the next step of a tool loop the model saw its own earlier steps
  with no thinking at all. Qwen's chat template renders the reasoning of every step since the last
  user message, and without it an agent loses its thread: one wrote a truncated file and then
  called `write_file` with no path. Hive now keeps a step's `reasoning_content` on the assistant
  message (stored with the conversation) and sends it back on the steps after the last user
  message, the scope these templates read. Reasoning from earlier turns is not sent. Anthropic's
  signed `thinking_blocks` work as before.
- **Saving a provider in an installed Hive.** The server checked API keys with code it imported
  from the repository's `scripts/` folder, which is not shipped, so saving a provider in Settings
  failed with `ModuleNotFoundError`. The key checks now live in the package
  (`framework.llm.key_check`); `scripts/check_llm_key.py` uses the same code.

## For code built on Hive

`FinishEvent` has a new field, `reasoning_content` (empty when a model streams none), and the
conversation's assistant `Message` has `reasoning_content` alongside `thinking_blocks`.

`aden-tools` is released at the same version, unchanged, because the `tools` extra pins it exactly.
