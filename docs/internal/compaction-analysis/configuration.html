LoopConfig field-by-field

core/framework/agent_loop/internals/types.py:48-131 
@dataclass
class LoopConfig:
    """Configuration for the event loop."""

    max_iterations: int = 50
    # 0 (or any non-positive value) disables the per-turn hard limit.
    max_tool_calls_per_turn: int = 0
    judge_every_n_turns: int = 1
    stall_detection_threshold: int = 3
    stall_similarity_threshold: float = 0.85
    max_context_tokens: int = 32_000
    # Headroom reserved for the NEXT turn's input + output so that
    # proactive compaction always finishes before the hard context limit
    # is hit mid-stream. Scaled to match Claude Code's 13k-buffer-on-
    # 200k-window ratio (~6.5%) applied to hive's default 32k window,
    # with extra margin because hive's token estimator is char-based
    # and less tight than Anthropic's own counting.
    compaction_buffer_tokens: int = 8_000
    # Ratio-based component of the hybrid compaction buffer. Effective
    # headroom reserved before compaction fires is
    #   compaction_buffer_tokens + compaction_buffer_ratio * max_context_tokens
    # ... Defaults: 8k + 15%.
    # On 32k that's a 12.8k buffer (~60% trigger); on 200k it's 38k
    # (~81% trigger); on 1M it's 158k (~84% trigger).
    compaction_buffer_ratio: float = 0.15
    # Warning is emitted one buffer earlier so the user/telemetry gets
    # a "we're close" signal without triggering a compaction pass.
    compaction_warning_buffer_tokens: int = 12_000
    store_prefix: str = ""

    # Tool result context management.
    # Lowered from 30_000 → 12_000 to reduce per-turn request density.
    max_tool_result_chars: int = 8_000
    spillover_dir: str | None = None

    # Image retention in conversation history.
    # ... Raise this only if you genuinely need longer visual history AND
    # you know your provider is using native image tokenization.
    max_retained_screenshots: int = 2

    # set_output value spilling.
    max_output_value_chars: int = 2_000

Model-specific behavior — what does NOT exist

There is no model-specific compaction code
Compaction does not branch on the model name. The only model-dependent input is max_context_tokens, which the LLM wrapper supplies from core/framework/llm/model_catalog.json. Switching from Sonnet to Opus changes the absolute trigger but not the algorithm. Likewise, there is no “use this prompt for Haiku” branch — the Stage 2 summary prompt is the same for every provider.

How to widen or effectively disable compaction

There is no first-class “off” switch. Compaction is a safety mechanism — without it, the agent silently exceeds the provider’s window and 400-errors mid-stream. Practical ways to soften or widen it:

Raise max_context_tokens

Most direct way. The trigger is relative to this value via the hybrid buffer, so increasing it proportionally raises both the absolute fire point and the absolute headroom reserve. Override via the global config file:

// ~/.hive/configuration.json
{ "llm": { "max_context_tokens": 872000 } }

Shrink the buffer

Set LoopConfig.compaction_buffer_ratio = 0.05 (5%) instead of 0.15 to push the trigger from ~81% to ~93% on a 200k window. Risk: less headroom for the next turn’s LLM call plus tool results, increasing the chance Checkpoint 3 (pre-send guard) has to fire mid-iteration.

Setting max_context_tokens=0

The conversation treats this as “unlimited” and needs_compaction() always returns False. The pre-send guard (usage_ratio() >= 1.0) also short-circuits because usage_ratio() returns 0.0. Do not do this in production unless you have an external truncation strategy — the provider will still reject oversize requests.

Disabling LLM compaction specifically

Stage 2 is skipped automatically if ctx.llm is None at compaction.py:297. There’s no separate config flag for this; setting up a node without an LLM context handle is the mechanism. The pipeline still runs Stages 0–1 and then falls through to Stage 3 emergency if needed.

Where each value flows in the runtime

core/framework/agent_loop/agent_loop.py:4217-4241 
async def _compact(
    self,
    ctx: AgentContext,
    conversation: NodeConversation,
    accumulator: OutputAccumulator | None = None,
) -> None:
    """Compact conversation history to stay within token budget."""
    return await compact(
        ctx=ctx,
        conversation=conversation,
        accumulator=accumulator,
        config=self._config,
        event_bus=self._event_bus,
        char_limit=self._LLM_COMPACT_CHAR_LIMIT,
        max_depth=self._LLM_COMPACT_MAX_DEPTH,
    )

self._config is the live LoopConfig — its max_context_tokens, spillover_dir, buffer fields, and tool/screenshot caps reach every stage through this single argument. self._event_bus is what carries the CONTEXT_COMPACTED event to the desktop UI.

Per-conversation persistence

The three compaction buffer fields on NodeConversation (compaction_buffer_tokens, compaction_buffer_ratio, compaction_warning_buffer_tokens) are serialized into meta.json when the conversation is persisted, so a restored conversation uses the same trigger it was originally configured with — even if the global default has since changed. See the serialization/restore path in the same file. Default-restore behavior at conversation.py:1698 falls back to 0.8 for the legacy threshold if buffers are absent.
