What gets compacted away — and what stays

Compaction is not symmetric: some categories of content are protected at every level, others get truncated, others get moved to disk with a recovery hint, and the rest get summarized or dropped. This page enumerates the exact rules and shows before/after examples.

2026-05-12 update
The structure-preserving stage and its tool-call-argument compaction helper (_compact_tool_calls, the {"_compacted": "…"} sentinel) were removed from the pipeline. See Audit for the rationale. The dedicated discussion of those artefacts below is retained because existing on-disk session data still contains them and you may need to understand what you’re reading. New compactions do not produce them.

Always preserved (across every level)

CategoryWhySource
Recent messages The N most recent messages are kept verbatim (keep_recent = 2 in Stage 2 LLM summary, 1 in Stage 3 emergency). The agent needs the immediate-prior tool result and assistant turn to continue coherently. conversation.py:1219-1296
Transition markers is_transition_marker=True messages are never pruned and are always kept structurally. They sit at phase boundaries and are how the agent finds its position in a continuous-mode workflow. conversation.py:1079 · 1385
Error tool results A pruned error result tempts the model to re-call the failing tool. Keeping the error in context makes the cost of the retry visible. conversation.py:1084
Skill content is_skill_content=True tool results carry activated SKILL.md instructions. Compacting them would let the agent forget a skill mid-task — the AS-10 invariant. conversation.py:1086
Current-phase messages In continuous mode, every message tagged with the active phase_id is exempt from pruning regardless of token pressure. conversation.py:1096
Tiny tool results (<100 chars) Usually set_output acks. Pruning saves nothing but might confuse the model into thinking the call failed. conversation.py:1090-1094
Already-pruned messages Content starting with "Pruned tool result" or "[Pruned tool result" is skipped — the placeholder is already minimal. conversation.py:1088
Output-key values Before discarding old messages in compact(), the conversation extracts any output_keys values found and re-injects them as PRESERVED VALUES at the top of the new summary message. conversation.py:1266-1276

Tool-call argument compaction (the “_compacted” sentinel) — historical

Removed 2026-05-12
_compact_tool_calls and the _TC_ARG_LIMIT constant were removed when the structure-preserving stage was deleted (see Audit). The subsection below is retained so readers inspecting archived sessions can recognise the sentinel pattern. New compactions never emit it.
core/framework/agent_loop/conversation.py:210-258 
_TC_ARG_LIMIT = 200  # max chars per tool_call argument after compaction


def _compact_tool_calls(tool_calls: list[dict[str, Any]]) -> list[dict[str, Any]]:
    """Truncate tool_call arguments to save context tokens during compaction.

    Preserves ``id``, ``type``, and ``function.name`` exactly.  When arguments
    exceed ``_TC_ARG_LIMIT``, replaces the full JSON string with a compact
    **valid** JSON summary.  The Anthropic API parses tool_call arguments and
    rejects requests with malformed JSON (e.g. unterminated strings), so we
    must never produce broken JSON here.
    """
    compact = []
    for tc in tool_calls:
        func = tc.get("function", {})
        args = func.get("arguments", "")
        if len(args) > _TC_ARG_LIMIT:
            # Build a valid JSON summary instead of slicing mid-string.
            try:
                parsed = json.loads(args)
                if isinstance(parsed, dict):
                    summary_parts = []
                    for k, v in parsed.items():
                        v_str = str(v)
                        if len(v_str) > 60:
                            v_str = v_str[:60] + "..."
                        summary_parts.append(f"{k}={v_str}")
                    summary = ", ".join(summary_parts)
                    if len(summary) > _TC_ARG_LIMIT:
                        summary = summary[:_TC_ARG_LIMIT] + "..."
                    args = json.dumps({"_compacted": summary})
                else:
                    args = json.dumps({"_compacted": str(parsed)[:_TC_ARG_LIMIT]})
            except (json.JSONDecodeError, TypeError):
                # Args were already invalid JSON — wrap the preview safely
                args = json.dumps({"_compacted": args[:_TC_ARG_LIMIT]})
        compact.append(
            {
                "id": tc.get("id", ""),
                "type": tc.get("type", "function"),
                "function": {
                    "name": func.get("name", ""),
                    "arguments": args,
                },
            }
        )
    return compact

Why a JSON sentinel rather than a slice
Direct truncation at 200 chars would frequently produce mid-string JSON like "arguments": "{\"url\": \"https://exa — the Anthropic API rejects that as malformed. Wrapping the preview in a valid object guarantees the request will at least serialize correctly. The function’s exception arm at conversation.py:245-247 handles the case where the source arguments were already broken JSON to begin with.

Spillover file format (historical)

Removed 2026-05-12
Numbered conversation_N.md spillover files were produced by the structure-preserving stage. New compactions do not produce them. Existing on-disk archives may still contain them; the format below documents what you’re looking at when you find one.

The format is intentionally prose, not JSON or bracketed structure: 

## Compacted conversation (messages 1-12)

[user] (seq=0): Hi, please analyse the attached log file for memory issues.

[assistant] (seq=1): I'll start by examining the file structure to identify ...

[user] (seq=4): That looks promising. Can you also check the GC pause distribution?

[assistant] (seq=5): Good idea. Let me extract the GC events ...

The reference message that takes the place of those freeform messages:

Previous conversation saved at: /home/timothy/.hive/agents/.../data/conversation_1.md
Read the full transcript with read_file('conversation_1.md').

TOOLS ALREADY CALLED:
  read_file (3x):
    - /tmp/server.log
    - /tmp/gc.log
    - /etc/jvm.conf
  web_search (1x):
    - "G1GC pause analysis"

In aggressive mode this is followed by a fuller tool-call history extracted from the collapsed pairs, built by extract_tool_call_history() at conversation.py:261-324.

Image stripping in LLM compaction

core/framework/agent_loop/internals/compaction.py:381-409 
def strip_images_from_messages(messages: list[Message]) -> list[Message]:
    """Strip image_content from messages before LLM summarisation.

    Images/documents are replaced with ``[image]`` markers so the summary
    notes they existed without wasting tokens sending binary data to the
    compaction LLM.  Returns a new list (original messages are not mutated).
    """
    stripped: list[Message] = []
    for msg in messages:
        if msg.image_content:
            n_images = len(msg.image_content)
            marker = " ".join("[image]" for _ in range(n_images))
            content = f"{msg.content}\n{marker}" if msg.content else marker
            stripped.append(
                Message(
                    seq=msg.seq, role=msg.role, content=content,
                    tool_use_id=msg.tool_use_id, tool_calls=msg.tool_calls,
                    is_error=msg.is_error, phase_id=msg.phase_id,
                    is_transition_marker=msg.is_transition_marker,
                    image_content=None,  # stripped
                )
            )
        else:
            stripped.append(msg)
    return stripped
Why this matters separately from compaction
Each full-page screenshot can cost ~250k tokens on providers that bill image content as text (gemini and most non-Anthropic providers). Four screenshots can push a session past gemini’s 1M-token window and trigger garbage output. Stripping them before the compaction LLM call avoids paying those tokens twice — once to fit them into the conversation, again to feed them to the summarizer. conversation.py:1147-1170 documents the parallel per-turn evict_old_images() path.

The compact() message-replacement summary path

core/framework/agent_loop/conversation.py:1247-1295 
if split is None:
    # Fallback: use keep_recent (non-phase or single-phase conversation)
    keep_recent = max(0, min(keep_recent, total - 1))
    split = total - keep_recent if keep_recent > 0 else total

# Advance split past orphaned tool results at the boundary.
# Tool-role messages reference a tool_use from the preceding
# assistant message; if that assistant message falls into the
# compacted (old) portion the tool_result becomes invalid.
while split < total and self._messages[split].role == "tool":
    split += 1

# Nothing to compact
if split == 0:
    return

old_messages = list(self._messages[:split])
recent_messages = list(self._messages[split:])

# Extract protected values from messages being discarded
if self._output_keys:
    protected = self._extract_protected_values(old_messages)
    if protected:
        lines = ["PRESERVED VALUES (do not lose these):"]
        for k, v in protected.items():
            lines.append(f"- {k}: {v}")
        lines.append("")
        lines.append("CONVERSATION SUMMARY:")
        lines.append(summary)
        summary = "\n".join(lines)

# Determine summary seq
if recent_messages:
    summary_seq = recent_messages[0].seq - 1
else:
    summary_seq = self._next_seq
    self._next_seq += 1

summary_msg = Message(seq=summary_seq, role="user", content=summary, run_id=self._run_id)
Two safety invariants enforced here
  1. No orphaned tool results. The split point is advanced past any tool-role messages that would otherwise lose their parent assistant message. A tool result without its tool call would be rejected by the API.
  2. Output values are protected. If the node has declared output_keys and any of those values are already set in the messages being discarded, they’re extracted and prefixed to the summary as PRESERVED VALUES so the running OutputAccumulator doesn’t lose them.

Three labels surface to the runtime logger and event bus: prune_only means the cheaper stages were enough (or the LLM stage was bypassed), structural is a legacy label from when the structure-preserving stage existed; it survives in the labelling code for backwards compatibility but new pipelines do not produce it, and llm means a successful LLM summary call drove usage to 60% or lower.
